目标为正式 Java **26.3**，核对日期 2026-10-30。证据来自 [Mojang 26.3 元数据](https://piston-meta.mojang.com/v1/packages/5df1795e16eea19d75b923d66ecca9ce183353c5/26.3.json) 指向的官方客户端，SHA-1 `e877b6a07acd633fb3bb475002175cec036e7b87`。使用 JDK 25 `javap -p -c` 检查具名方法的常量、计算顺序和分支，`physics-26.3-evidence.json` 记录所核对 class 的 SHA-256。项目独立编写 TypeScript 实现，没有将官方运行时 class 打包进网页。

## 核实并接入的基础算法

| 依据 | 行为 |
|---|---|
| `KeyboardInput.tick`、`LocalPlayer.modifyInput` | 键盘方向先归一化；输入乘 `0.98f`；使用物品与潜行分别乘当前默认倍率 `0.2f` / `0.3f`；随后执行最新版的正方形输入速度调整。保留摇杆幅度，不能把减速后的方向再次强制归一到全速。 |
| `Player.createAttributes`、`LivingEntity` 疾跑属性修饰 | 默认地面移动属性 `0.1f`，疾跑乘 `1 + 0.3f`。输入逐刻加到现有惯性，替代以前每刻覆盖速度的实现。 |
| `LivingEntity.getFrictionInfluencedSpeed` | 贴地且方块 friction 大于 `0.6` 时，加速度为 `speed × 0.21600002f / friction³`；否则为 speed。这是本次直接核实的 26.3 分段条件。 |
| `LivingEntity.travelInAir` | 加速→移动/碰撞→扣重力→阻力。默认水平保留 `friction × 0.91f`，竖直为 `(vy - 0.08) × 0.98f`。空中 friction 为 1。 |
| `Player.getFlyingSpeed` 的非创造分支 | 空中移动加速度为 `0.02f`，疾跑为 `0.025999999f`；转向和松键都保留原有惯性。 |
| `LivingEntity.aiStep` | 玩家水平速度向量的长度平方小于 `9e-6` 时归零；竖直绝对值小于 `0.003` 时归零。不能逐轴套玩家的水平阈值。 |
| `LivingEntity.jumpFromGround`、`Attributes.JUMP_STRENGTH` | 起跳竖速取 `max(vy,0.42f)`，疾跑另沿视角方向增加 `0.2` 水平冲量；起跳这一刻仍使用地面加速度/摩擦。 |
| `LivingEntity.aiStep` | 按住跳跃时，起跳后间隔 10 刻；松开立即清掉间隔。落地后可继续跳，浅水/深水分支按是否接地及水深 `0.4` 区分。 |
| `jumpInLiquid` / `goDownInWater` | 每刻给竖速增加/减少 `0.04f`，替代原来水里按一次空格直接设 `0.5` 竖速的错误。未接地的浅水上浮也使用液体冲量，不能凭靠近水面给完整陆地跳跃。 |
| `travelInWater`、`getFluidFallingAdjustedMovement` | 默认水平加速度 `0.02f`，水平阻力 `0.8f`、疾跑 `0.9f`，竖直阻力 `0.8f`。非疾跑水中重力为 `0.08 / 16 = 0.005`，并保留核实的临界速度分支。 |
| `jumpOutOfFluid`、`Entity.isFree` | 只有水平撞到障碍，且按官方偏移检查的上方包围盒完全无固体和液体时，才给 `0.3f` 上岸助推；开阔深水没有该助推。 |
| `Blocks`、`Entity.move/getBlockSpeedFactor` | 冰和浮冰 friction `0.98f`；灵魂沙速度因子 `0.4f` 在实际位移之后、travel 阻力之前施加，不是简单将输入速度乘 0.4。移动支持方块偏移核实为 `0.500001f`。 |

普通地面直线稳定行走约 **4.317 格/秒**，疾跑约 **5.612 格/秒**；首刻行走只有约 **0.098 格**，随后逐步加速。`Player.vel` 保存末尾阻力后的惯性，不等于刚刚发生的位移。贴地时 `onGround=true` 与 `vel.y≈-0.0784` 可以同时成立：下一次碰撞先去掉该向下速度，末尾再施加重力。地面判断不能依赖 `vy===0`。

## 游戏接线与兼容

- `MoveIntent.jump` 保留边沿调用；新增可选 `jumpHeld` 接持续空格，`swimUp` 保留液体上浮语义。`Player.jumpDelayTicks` 缺省为 0，旧存档不需要迁移。
- `Player.didJumpFromGround` 仅本次实际起跳为 true，每步重置。音效和饥饿消耗应读取这个事件，避免漏掉按住空格后的再次起跳，也避免把水中上浮记作地面跳。
- `kbx/kbz` 是游戏层提交的一次待消费冲量，进入下一刻惯性后归零，再随介质阻力衰减。该接入修正避免每刻重复叠加；并未声称实现原版所有伤害来源的击退计算。
- 现有逐轴碰撞、潜行边缘保护、受限空间保持矮姿态和创造飞行分支保留。创造飞行仍使用项目原有速度控制，本轮不将其列入已完成的原版算法。

## 尚未一比一的部分

当前世界物理接口只有完整体素的 `isSolid/isWater`。水体接触改为检查整个玩家包围盒，仍把每个水格视为满格，尚无按流体等级变化的真实水面、流速和浮力修正。正式版的奔泳姿态、看向方向的游泳竖直转向、爬行、鞘翅、梯子/藤蔓、岩浆、气泡柱、海豚效果、深海探索者、灵魂疾行、跳跃/速度药效等未接入。

碰撞继续使用项目的 Y→X→Z 扫掠和距脚下 0.06 格的接地探针，未移植原版复杂碰撞形状、自动上台阶、支持面选择或精确潜行退边算法。灵魂沙本轮只有速度因子，碰撞高度仍是项目整块形状。斜向视角旋转用 JavaScript 三角函数，没有复现原版查表/浮点角度的全部舍入细节。部分输入与疾跑条件由 `Game` 决定；这些边界均不包含在本轮公式轨迹吻合的结论中。
