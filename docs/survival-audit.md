# 生存与姿态规则核对：目标 Java 26.3

核对日期：2026-10-30。用户已将目标从 Java 1.12 改为当日稳定版 **Java 26.3**；[官方 26.3 发布说明](https://feedback.minecraft.net/hc/en-us/articles/48913133328013-Minecraft-Java-Edition-26-3) 和[官方版本清单](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json)用于确定目标，不采用 26.4 snapshot。这里记录独立浏览器实现已经核对的局部规则和仍存在的限制，不表示整个 Mineworld 已与该版本一致。未获取或复制原版源码。

## 本轮确定修复

1. **低饱和度快速回血。** 食物为 20 且有饱和度时，每 10 个模拟刻恢复 `min(saturation, 6) / 6` HP，并增加 `min(saturation, 6)` 耗竭；例如饱和度 3 应回 0.5 HP、增加 3 耗竭。此前所有饱和度都固定回 1 HP、增加 6 耗竭。依据：[Food 内部变量和耗竭表](https://minecraft.wiki/w/Food#Internal_variables)。每 1 HP 是半颗心，6 耗竭/HP 的规则自 Java 1.11 已采用。
2. **死亡后不自然回血。** 快、慢回血均要求 `health > 0`。旧实现会在先溺水扣至 0 HP、后结算自然回血的同一刻重新变成正血，跳过死亡检查；已用游戏实际调用次序补回归。
3. **现代出水回气。** 陆上每刻恢复 4 air，封顶 300；从 0 恢复到 300 需 75 刻（3.75 秒），不再一刻回满。潜水每刻消耗 1 air，到 −20 扣 2 HP 并将 air 重置为 0。现有文档对“每气泡”的时间有不同表述，本项目按空气计数单位实现。[MCDF 的直接研究记录](https://mcdf.wiki.gg/wiki/Java_Edition:Drowning_Drowning-Immune_Mob#Preservation)明确记录现代实体离水每刻增加 4 的 Air 行为；[原作实体数据格式](https://minecraft.wiki/w/Entity_format)记录 Air 的刻数含义。这里不是 26.3 客户端逐帧实测记录。
4. **现代潜行姿态。** 碰撞高度从 1.8 改为 **1.5**，眼高从 1.54 改为 **1.27**。松开按键时，如果当前位置只能容纳矮姿态，仍保持矮姿态，直到站立空间足够。依据：[Player 的尺寸、视点及 1.14 历史记录](https://minecraft.wiki/w/Player#Trivia)。

普通难度饥饿阈值保留为 1 HP，即半颗心；修正旧注释将其称作“一心”的错误。食物 0 时每 80 刻进行一次饥饿判定，当前实现健康值高于 1 HP 才扣 1，不新增未核实的小数边缘规则或其它难度。

## 氧气如何兼容旧存档

没有增加 `airTicks` 字段，也没有改变 `oxygen / oxygenTimer` 的类型或存档单位。旧数据可直接恢复：

```text
air = oxygen × 30 − oxygenTimer
```

当 air 为正时，编码为 `oxygen = ceil(air / 30)`、`oxygenTimer = oxygen × 30 − air`；air 不大于 0 时，`oxygen = 0`、`oxygenTimer = −air`。所以原来“7 个气泡、经过 5 刻”的状态仍表示 205 air；现代出水恢复到 44 air 则编码为 2 气泡、计时 16。现有存档验证允许氧气整数 0..10、计时整数 0..30，可容纳所有这些状态。

新增 `oxygenAirTicks(s)` helper 可供 HUD 读取精确空气。离水恢复期间的负 air 仍保留欠量，不会靠出水一瞬清除溺水等待：−19 出水一刻为 −15，再入水一刻为 −16。仅水下到 −20 时扣血，陆上恢复不扣血。

[Damage 的 2017-09-04 历史记录](https://minecraft.wiki/w/Damage?oldid=1144112#Drowning)用于交叉核对保留的基础时序：300 刻耗尽空气、第 320 刻第一次扣血、之后每 20 刻扣 2 HP。历史资料不用于证明现代陆上恢复速度。

## Game 接口

本 agent 未修改 `Game.ts`，集成由主实现负责：

- 仍按 **20 TPS** 调用 `tickOxygen(s, headInWater)` 与 `tickSurvival(s)`，不按渲染帧率推进；Game 的创造模式绕过、伤害反馈和死亡处理保持原接口。
- `Player` 新增可选 `crouching`，表示碰撞解算后实际姿态。旧 player 对象未带此字段时视为直立。`step()` 返回它；Game 必须在解算后使用它更新相机，而不能只看是否按住 Shift。
- 新 helper `playerEyeHeight(player)` 返回实际姿态眼高（1.62 或 1.27），用于水下眼点、射线与弹射起点。`playerHeight(player)` 返回 1.8 或 1.5，供放置时的玩家碰撞等判断使用。
- 相机可以继续视觉插值，但判定头是否入水应使用实际姿态眼高，不能使用固定 EYE 或尚在插值中的摄像机高度。
- 血量允许小数；HUD 应先向上取整后绘制整/半颗心，不能仅用小数值 `=== 1` 判断半心。

## 已核对并报告主实现的其它现代差异

- [Leaves](https://minecraft.wiki/w/Leaves)：自然叶片沿树叶连接到支撑木的最大距离为 **6**，距离 7 无支撑；玩家放置的 persistent 树叶不自行腐烂。1.13 的版本记录明确由 4 改为 6。未由本 agent 修改树叶模块。
- [官方 Java 1.18 更新说明](https://feedback.minecraft.net/hc/en-us/articles/4415128577293-Minecraft-Java-Edition-1-18)：通常主世界自然怪物生成要求 **方块光为 0**，天空光仍单独限制。不能把两种光合并成“所有光都必须为 0”，也不能推广到每一种怪物或生成器。未由本 agent 修改刷怪模块。

## 仍未覆盖，不能称为完整现代实现

**一格高爬行、完整游泳姿态及触发条件仍未实现。** 普通潜行的 1.5 高碰撞箱不是爬行的 0.6 高姿态，不能直接放行一格洞。当前世界碰撞接口按实心整方块提供，没有完整的半砖、活板门等可变碰撞形状；测试中的 1.5 头部空间用玩家足部与体素顶棚间距验证，不据此声称所有半砖通道已实现。

还未涵盖呼吸附魔、水下呼吸药水、完整难度选择、所有伤害免疫交互、现代游泳加速度/阻力、玩家缩放属性和全部移动姿态。现有移动器里仍保留部分旧近似，不能把修改两项尺寸说成完整 26.3 物理复制。普通饥饿的小数边缘行为也没有新增未经核实的特殊处理。

## 验证范围

生存测试覆盖低饱和度回血/耗竭、同刻耗竭结算顺序、死亡不可回活、生命上限、半心饥饿阈值、潜水第 299/300/319/320/339/340 刻、75 刻回气、短暂出水负 air、旧字段恢复与回气后再次存读档。姿态测试覆盖 1.5/1.27 尺寸、受限顶棚松键仍矮、离开受限空间恢复站立、普通潜行不可冒充一格高爬行。相关生存/物理/存档 **86 项测试通过**，全项目 TypeScript 类型检查通过；这不替代浏览器实玩和原版逐帧对比。
